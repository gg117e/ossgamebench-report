# 最終PR差分によるテスト候補の再計測（2026-11-13）

CHECKPOINT.md の最優先課題への対応。v1（07）は PR に結び付く**全コミットのパスの和集合**でテスト候補を判定していたため、
PR の途中で master を取り込んだマージコミット（`Merge branch 'master' into ...`）の変更まで数えていた。
ここでは PR ごとに**取り込まれた最終差分**（ランディングコミット）だけを使って測り直した。

## 方法（`scripts/11_final_pr_diff.py`）

データには親コミットも `merge_commit_sha` もないので、ランディングコミットはメッセージの 1 行目で識別する。

| PR の状態 | 条件 | 扱い |
|---|---|---|
| landing_unique | `Merge pull request #N ...` または末尾が `(#N)` のコミットが 1 つ（Revert を除く、パスが 1 つ以上） | そのパスを最終差分とする |
| landing_equivalent | 上の候補が複数あるが、パスの集合が同じ（チェリーピックなど） | 同上 |
| landing_ambiguous | 候補が複数あり、パスの集合が異なる | 主分析から除く |
| no_landing | 候補がない | 最終差分は不明。PR 自身の非マージコミットの和集合を感度分析用にだけ保存 |

Issue 単位では、リンクしたマージ済み PR の**すべて**に最終差分がある場合（all_landing）だけを主分析に使う。
テスト候補の判定規則は v1 と同じ（パスの規則、未検証）。

## GitHub との照合（`scripts/12_check_final_diff_github.py`）

公開 GitHub API（`gh api repos/{owner}/{repo}/pulls/{n}` と `.../files`）で、PR の変更ファイル一覧と比べた。
送ったのはリポジトリ名と PR 番号だけ。シードは 20261113、各層 25 件。取得結果のキャッシュは
`C:/Users/<user>/ossgamebench-data/interim/final_diff_v1/github_cache/`、行ごとの結果は `github_check_rows.json`。

## 解釈の注意

- 照合は 74 件のサンプルで、一致率に信頼区間は付けていない。ランディングコミットを識別できない PR（no_landing、ambiguous）は照合していない。
- 「テスト候補あり」は、パスの規則で最終差分にテストらしいファイルが含まれることを示すだけ。当該バグの回帰テストであること、実行されたことは示さない。
- game の 6.21% は、**プロジェクトの範囲分類（LLM による暫定、人の検証前）**とパスの規則（未検証）に依存する。
